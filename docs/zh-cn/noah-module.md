# Noah Module 开发规范

Module（其他守护进程 agent）是由 Noah 系统托管的第三方系统 agent，通过 Zeus 插件启动和管理，部署于 `/opt/noah/modules/`。本文档介绍 Module 的开发规范和最佳实践。

## 1. 目录结构

```
modules/
└── module_name/
    ├── main.go
    ├── config/
    ├── bin/
    └── README.md
```

接口规范：每个 module 必须实现健康检查、日志输出、状态反馈接口，便于 Zeus 管理。

## 2. 限制规范

- **资源与权限**：限制 CPU、内存使用量，防止系统资源消耗过多。
- **包大小**：单个 module tarball 包大小应控制在 **100MB** 以内，超过则不允许上传。

## 3. 文件权限规范

- 只有可执行文件才有执行权限，正常为 `755`。
- 其他文件应为只读，正常为 `644`。

## 4. 包管理规范

Module 包的结构与 deb 包类似：

```
.
|-- changelog
|-- control
|-- ROOT
|-- preinst
|-- postinst
|-- prerm
`-- postrm
```

| 文件 | 说明 |
| --- | --- |
| `changelog` | 记录软件包的更改历史：版本更新内容、修复的错误、新功能等，方便用户和维护者了解每次更新 |
| `control` | tarball 的核心文件，包含软件包元信息（包名、版本、描述、依赖关系等），帮助包管理系统解析包名、依赖和适用环境 |
| `ROOT` | 包中文件的目标位置映射，Noah 会将其中的文件安装到系统中对应的位置 |
| `preinst` | 安装前脚本：准备安装环境，如停止旧版本服务、备份旧配置文件 |
| `postinst` | 安装后脚本：安装后配置或初始化，如创建目录、配置系统服务、设置权限、生成缓存 |
| `prerm` | 卸载/升级前脚本：停止相关进程，避免文件占用或冲突，为新版本安装做清理 |
| `postrm` | 卸载后脚本：清理残留文件（缓存、日志等），确保卸载后系统状态干净 |

## 5. 下载安装流程

1. **下载 `.md5` 文件**：获取软件包的 MD5 校验值，检查 `modules/{md5}/` 路径是否存在。
   - 如果存在，跳过下载，直接进行安装。
   - 如果不存在，继续下载软件包。
2. **下载 `.tar.gz` 文件**：下载软件包压缩包，比对 MD5 校验值，确保文件完整。
3. **解压缩**：解压下载的软件包。
4. **安装**：根据软件包的内容（`ROOT` 映射及 `preinst`/`postinst` 脚本），执行相应的安装操作。

下载路径规范见[系统架构文档](architecture.md#6-下载与分发规范)。
